# 弹簧振子轨迹预测 · 实现说明

用 `弹簧小球-vue3-物理增强版.html` 的物理内核生成仿真数据，训练一个小型神经网络学习
**无量纲化的向量场**，再把权重导成纯 JSON 交给浏览器做自回归推演，在画布上以虚线叠加显示。

物理范围按需求收窄为：**只有弹簧弹力 + 线性粘滞阻尼 + 重力**，去掉了空气阻力和地面碰撞。

---

## 2. 结果

测试集 150 条**完全没见过的轨迹**（参数和初值都不同），用学到的向量场做 40 个无量纲时间单位
（≈ 6.4 个振荡周期）的自回归：

| 指标 | 数值 |
|---|---|
| 单步加速度 RMSE | 1.23e-2 |
| ADE（全时域平均位移误差） | **0.013 L0** |
| FDE（末端位移误差） | **0.020 L0** |
| VPT@0.10·L0 | 40 τ（**全程未超过 10% L0**） |
| 振荡周期相对误差 | **0.22 %** |

误差增长是次线性的：τ=1 时 0.0038 L0，τ=4 时 0.0119，τ=40 时 0.0200。

`单步加速度 RMSE` 看着不小（1.2e-2），但它在自回归里符号基本随机、互相抵消，
真正决定长时域的是**系统性偏差**——所以周期误差 0.22% 才是关键数字，而不是单步 RMSE。

## 3. 数据生成

### 3.1 不从浏览器采

页面用 `requestAnimationFrame` 推进，导出的是帧序列、帧间隔抖动；而且 `reset()` 永远把小球
放在同一个位置、速度为 0，跑一万次也只有**一个**初始条件。

正确做法是把 `deriv / rk4` 搬到 Python 批量跑。校验过：同一初值跑 5 秒 1200 帧，
Python 与 HTML 的最大偏差 **2.2e-12 px**（纯 float64 舍入）。

### 3.2 无量纲化

令 `ω0 = sqrt(k/m)`、`R = r/L0`、`τ = ω0·t`、`V = dR/dτ`，运动方程变成

```
d²R/dτ² = -(|R| - 1)·R̂  -  2ζ·V  +  γ·ŷ
ζ = c/(2√(km))          γ = mg/(kL0)
```

右边**只剩两个标量参数**，`m` 和 `L0` 彻底消失（它们只决定长度和时间尺度的换算）。
这就是为什么 1500 条轨迹、24 万个样本就能把这个"族"学到 1% 以内——
参数空间从 5 维塌缩成 2 维。

`γ` 的物理含义很直白：平衡伸长量 `L_eq = L0·(1+γ)`，也就是静态下垂比例。

### 3.3 采样

- `ζ`、`γ` 在无量纲空间做拉丁超立方，`ζ ∈ [0.02, 4]` 对数均匀，`γ ∈ [0, 4]` 对数均匀，
  另强制 15% 的 `γ = 0`（无重力是定性不同的分支，纯对数采样会漏掉）
- 初值围绕平衡半径取 0.55~1.40 倍，一半给切向速度、一半给任意方向
- 每条轨迹 τ∈[0,40]，步长 dτ=0.04，1000 步

### 3.4 两个数据坑（都踩过）

**坑一：奇异性污染整个数据集。**
`|R| → 0` 时方程里有 `1/|R|` 型奇异，定步长 RK4 会在这一步注入巨大能量，轨迹直接飞到
`|R| = 400+`。这些样本一旦混进来，就把输入输出的归一化统计量整个带偏
（实测 `Ry` 的标准差被拉到 75，网络看到的几乎是无结构的输入，怎么训都只有 17% 的 loss 下降）。
现在用**能量单调性**做拒绝采样：阻尼存在时 `E = ½|V|² + ½(L-1)² - γ·Ry` 必须单调不增，
只要出现能量上升就整条丢掉。拒绝率 26%。

**坑二：一半样本是"已经停稳"。**
阻尼大的轨迹跑几个周期就贴在平衡点上不动，加速度中位数只有 0.01。这些样本占了一半以上，
却把输出归一化尺度压小，让"一律输出 0"变成一个低 loss 的解——loss 很好看，rollout 完全不能用。
现在会丢掉"|V| < 0.05 且 |R - L_eq| < 0.05"的样本，只保留 15% 作为平衡点附近的锚。

## 4. 模型与训练

| 项 | 取值 |
|---|---|
| 结构 | `8 → 96 → 96 → 2`，SiLU，10,370 参数 |
| 输入 | `Rx, Ry, Vx, Vy, log ζ, log γ, |R|, 1/|R|` |
| 输出 | 无量纲加速度 `(aRx, aRy)` |
| 损失 | 归一化输出空间上的 MSE |
| 优化 | AdamW，lr 3e-3 余弦退火到 3e-5，30000 步，batch 1024 |
| 数据划分 | **按轨迹整条划分** 1200 / 150 / 150 |
| 训练耗时 | 约 3 分钟（纯 numpy，不需要 GPU） |

两处关键设计：

**输出选加速度而不是位置。** 加速度再配合 RK4 积分推进，积分器与生成数据用的是同一个，
误差源里就彻底没有"离散化方式不一致"这一项。

**把 `|R|` 和 `1/|R|` 显式喂进去。** 动力学项 `-(|R|-1)·R̂` 显含半径，不加这两列的话网络要
先学一个距离度量再学径向依赖，实测收敛慢一个量级（MSE 4.0e-4 vs 1.6e-4）。

> 没有做多步 rollout 训练，也没有做灰盒残差。原因是：仿真数据里真实的加速度是解析可知的，
> 直接拿它当标签监督向量场，是一个良定义、无偏、且便宜两个数量级的做法；而灰盒的解析项
> 在"完全复刻仿真器"的前提下就等于真值，残差恒为 0，没有意义。如果换成只有观测轨迹、
> 看不到加速度的数据，这两条都要补上。

## 5. 模型加载方式

三种，按场景选：

**(A) 本地双击打开（默认）** —— `file://` 下 `fetch` 会被 CORS 拦掉，所以权重走普通 script：

```html
<script src="spring_model.js"></script>
<script>
  const predictor = await SpringPredict.load('spring_model.json');
</script>
```

`load()` 的取用顺序是 `window.SPRING_MODEL` → `fetch(url)`。传参只是备选路径：
A 场景下 script 已经把全局变量写好了，`fetch` 根本不会触发。

**(B) http 部署** —— 删掉 script 标签，只留 `fetch`：

```js
const predictor = await SpringPredict.load('./spring_model.json');
```

**(C) 内联** —— 把 JSON 塞进 `<script type="application/json" id="m">` 再 `JSON.parse`，
适合单文件分发，代价是模型和页面绑死、无法单独更新。

`spring_model.json` 和 `spring_model.js` 的内容完全等价，都是 `train.py` 一次导出的。

## 6. 接口约定

### 6.1 模型文件格式 `spring-mlp-v1`

| 字段 | 含义 |
|---|---|
| `format` | `"spring-mlp-v1"`，加载方应校验 |
| `features` | 输入特征名与顺序，**共 8 项** |
| `outputs` | `["aRx","aRy"]` |
| `arch.hidden` | 隐层宽度，`[96,96]` |
| `arch.activation` | `"silu"`，即 `x / (1 + e^-x)` |
| `integrator` | `{type:"rk4", dtau:0.04}`，推演时必须用这个 dtau |
| `norm` | `xMean/xStd/yMean/yStd`，**逐特征**标准化参数 |
| `layers[]` | 每层 `{in, out, W, b}`，`W` 是 `[in][out]` 嵌套数组 |
| `validity` | 训练覆盖范围，越界即外推 |
| `metrics` | 训练时记录的评估指标 |

前向过程固定为：特征 → 逐维标准化 → 每层 `SiLU(xW + b)`（最后一层不激活）→ 反标准化。

### 6.2 JS API

```js
const P = await SpringPredict.load('spring_model.json');   // 或 SpringPredict.fromSpec(spec)
```

**`P.accel(Rx, Ry, Vx, Vy, zeta, gamma) -> [aRx, aRy]`**
输入无量纲状态与无量纲参数，返回无量纲加速度。返回的是新数组，可以安全持有。

**`P.rollout(state, params, {horizon}) -> Result`**
一次性推完整条轨迹。

**`P.stepper(state, params, {horizon}) -> Stepper`**
分片推进。`stepper.advance(30)` 每次最多推 30 个子步，`stepper.points` 持续累积。
整条一次算要 32 ms（会掉帧），分片后每帧 30 步约 3 ms。**两者结果逐位相同**（实测差 0）。

```js
const st = P.stepper(state, params, { horizon: 12 });
while (!st.done) { st.advance(30); /* 每帧做一点，随时可读 st.points */ }
```

**参数与返回**

```js
state   = { x, y, vx, vy }        // SI，位置/速度均相对悬点
params  = { k, m, c, g, L0 }      // SI
horizon                           // 无量纲时长 τ，默认 12

Result = {
  points: [{ tau, x, y, vx, vy }],   // SI，相对悬点；长度 = floor(horizon/dtau)+1
  ok:     boolean,                   // false 表示中途越界，已停止
  reason: string | null,
  dtau, omega0, zeta, gamma
}
```

`tau` 是这条预测轨迹的无量纲时间戳，换算成真实秒要除以 `omega0`：
`t_real = tau / omega0`。

### 6.3 坐标与单位

| 环节 | 单位 |
|---|---|
| 页面内部仿真 | 像素 / 像素每秒（`SCALE = 0.01 m/px`） |
| 调用 `rollout` 之前 | 必须换成 SI，且**相对悬点**，不是画布绝对坐标 |
| 模型内部 | 无量纲：`R = r/L0`，`V = v/(L0·ω0)`，`τ = ω0·t` |
| 画回画布 | `px = anchorX + r_x / SCALE`，`anchorY + r_y / SCALE` |

`ζ = c/(2√(km))`、`γ = mg/(kL0)` 由 `params` 现算，**不要传**——模型文件里没有它们的物理解释，
写死会让换参数时报错。

### 6.4 绘制约定

页面里三条线，颜色和线型都固定，方便对照：

| 元素 | 样式 |
|---|---|
| 真实运动 | 小球本体，实心 `#2f8f5b` |
| **网络预测** | 虚线 `[7,6]`，`#f5b13d`，2px，末端加 5px 空心圆 |
| 真实未来 | 实线 `rgba(104,220,163,.45)`，1.2px（只在预测开启时画，用来目测偏差） |

最小画法：

```js
ctx.save();
ctx.setLineDash([7, 6]);
ctx.lineWidth = 2;
ctx.strokeStyle = '#f5b13d';
ctx.beginPath();
res.points.forEach((p, i) => {
  const X = anchorX + p.x / 0.01, Y = anchorY + p.y / 0.01;
  i ? ctx.lineTo(X, Y) : ctx.moveTo(X, Y);
});
ctx.stroke();
ctx.restore();
```

`res.ok === false` 时线段只到越界前的那一点，界面应提示"外推"而不是照常画完——
硬画下去得到的是纯粹的编造。

## 8. 已知边界

- **碰撞和空气阻力没做**。碰撞是速度跳变，连续向量场表示不了，需要"检测 + 学到的 reset map"
  的混合模型；空气阻力只是给无量纲方程加一个 `-ε|V|V` 项（`ε = 0.02·L0/m`），重训即可。
- **`|R| < 0.18` 属外推**。弹簧被压到接近实心长度，且方向在悬点处有奇异性，训练集刻意避开了。
  页面遇到这种情况会停止外推并标橙。
- **`ζ > 4` 或 `γ > 4` 属外推**。滑块能拉到的极端组合（如 c=20、m=0.2、k=2 → ζ=15.8）超出训练范围。
- **状态完全可观测**。这里假设位置速度都是精确已知的；如果只有带噪位置观测，
  应该先用 Kalman 平滑求速度，并给训练输入加同级噪声——直接用差分会在 120 Hz 下把噪声放大约一万倍。
