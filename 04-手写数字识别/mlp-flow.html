接口层负责制

从磁盘上四个 gzip 文件，到网页画板上写下的一笔被认成一个数字 —— 中间发生了什么。 这份文档不解释反向传播怎么推导，只讲清每一环「进去什么、出来什么、坏了会怎样」。 你可以不懂梯度，但必须看得懂形状。

784 → 256 → 10 全连接 tanh + softmax Adam · lr 1e-3 · batch 128 · 10 epoch 203,530 参数 / 1.9 MB
01

核心理念：只管接口，不管内部

把整个训练过程想象成一排黑色的盒子，你只负责把管子接对。

深度学习的实践工作，可以被切成两层。契约层是盒子之间的接口：张量形状对不对得上、 数值范围是不是同一个量纲、标签和输出是不是同一套语义、跑完了怎么判断它到底行不行。 黑盒层是盒子内部：梯度怎么算出来的、Adam 那三个公式在干什么、softmax 的雅可比矩阵长什么样。

契约层 · 你负责

每个函数的输入输出形状、dtype、取值范围；数据预处理与训练时是否一致； 用什么指标判断成败；出问题时先怀疑哪一环。

为什么不能放手 这一层出错时不会抛异常。代码照常跑完，loss 照常下降，准确率停在 10%（等于瞎猜）。

黑盒层 · 交给工具

反向传播的链式法则推导、每个算子的梯度表达式、优化器的数学性质、 学习率调度曲线的设计。

为什么可以放手 这一层出错立刻报错，而且第 50 行一行 autograd.grad 就把整条反向通路包掉了。
全局原则 黑盒不等于不可知，等于用实验去探测。你不必知道 Adam 的数学，但要知道 「lr 从 1e-3 调到 1e-1 会震荡」「去掉 tanh 两层会塌成线性」。 前者是可查的公式，后者是可做的实验 —— 后者才是你该积累的东西。

全景：一次 python mnist_mlp.py 发生了什么

十一个步骤，四个阶段。形状的变化集中在前三个，之后都在 (batch, dim) 这个格式里打转。

阶段 C · 训练循环（这是唯一会重复的部分）
  1. 5
    前向forward() L40–41

    (b,784) → (b,h) → (b,10) logits。三次矩阵乘/加，一次激活。

  2. 6
    算损失loss_fn() L43–48

  4. 8

数据准备：三行代码，三个坑

你负责

main() 里第 161–166 行。看起来最没技术含量，实际上是整个流程里最容易静默出错的地方。

输入
X_train (60000,28,28) uint8 y_train (60000,) uint8
输出
X (60000,784) float64 Y (60000,10) float64
语义
每行一张图；每行一个 one-hot 分布
163X_train = X_train.reshape(X_train.shape[0], -1) / 255.0
164X_test  = X_test.reshape(X_test.shape[0], -1) / 255.0
165Y_train = one_hot(y_train, 10)
166Y_test  = one_hot(y_test, 10)
坑一 · 除以 255 不是可选优化 原始像素是 0~255。如果直接喂进去，W1 的乘积会放大 255 倍，梯度跟着放大， 第一步就可能把参数推到饱和区。现象是：loss 卡在 2.3 附近不动，或者直接 NaN。 顺带注意：mnist_loader.load_mnist() 其实自带 normalize=True 参数， 但 main() 没用它，而是自己在这儿除 —— 两种写法都行，混着写就容易除两次。这是典型的契约泄漏。
坑二 · 训练集和测试集必须用同一套预处理 代码里第 163 和第 164 行是两条独立的语句。任何只改了其中一条的改动（比如调试时给训练集加了个增强）， 都会让测试集准确率失去意义 —— 而且它不会报错，只会莫名其妙地偏低。
坑三 · one_hot 只接受整数标签 Y[np.arange(n), y] = 1.0 用标签当列索引。如果 y 是浮点数或者已经被转过一次 one-hot， 这一步会抛出 IndexError 或静默做错。这是少数会报错的契约问题，要珍惜它。

顺带说清 X 的第一维到底是什么：它既是「整个训练集 60000 张」，也是「一批 128 张」。 同一个变量名、同一个第二个维度 784，第一维随上下文变化。 这正是下一节要把形状单独拎出来讲的原因。

04

形状与参数：全部形状都由三个数决定

你负责

这一段就是你在写代码之前脑子里已经在跑的东西。它完全正确，而且只需要三个数。

设 b = 一批的图片数（batch size），d = 每张图的像素数（784）， h = 隐藏层神经元数，k = 类别数（10）。那么整个网络的每个形状都不需要记忆，代公式就有：

张量形状它是什么代码位置
X(b, d)b 张图，每张展平成 d 个数L163
W1(d, h)把 d 维输入投影到 h 维L35
b1(1, h)偏置，靠广播加到每一行L36
H(b, h)tanh(XW1 + b1)，隐藏层激活值L41
W2(h, k)把 h 维特征投到 k 个分数L37
b2(1, k)输出层偏置L38
Y(b, k)logits：还没归一化的分数L41
P̂(b, k)softmax 之后的概率，每行和为 1L46–47
为什么 b1 可以是 (1,h) 而不是 (b,h) 因为 NumPy 的广播规则：(b,h) + (1,h) 会把第 0 维复制 b 份，不额外占内存。 写 (h,) 效果一样。但如果误写成 (h,1)，它会把第 1 维复制 h 份 —— 第一次乘加就会报维度不匹配，反而是好事；真正危险的是那些碰巧能广播成功的形状。

05

前向与损失：两次矩阵乘，一个标量

前向你负责 · 损失细节可黑盒

整个模型本体只有两行代码。所有复杂度都在「这两行怎么被循环调用」上。

40def forward(W1, b1, W2, b2, xb):
41    return np.tanh(xb @ W1 + b1) @ W2 + b2

这一行做了四件事，顺序不能换：投影（@W1）→ 平移（+b1）→ 压非线性（tanh）→ 再投到 10 个分数（@W2 + b2）。 输出没有 softmax —— 这是刻意的。softmax 被挪进了损失函数里，因为 「softmax + 交叉熵」合起来算梯度更稳，autograd 处理起来也更省事。

坑 · tanh 是这个网络里唯一不能删的东西 如果去掉 tanh，网络变成 (XW1+b1)W2+b2 = X(W1W2) + (b1W2+b2) —— 两个矩阵乘可以合并成一个 (784,10) 的矩阵。两层网络塌回单层线性分类器， 表达能力退回 92% 左右（线性模型在 MNIST 上的天花板）。 形状不会报错，代码不会报错，只有准确率上不去。这是本文件里最隐蔽的一个坑。

损失函数：分类用交叉熵，别用 MSE

43def loss_fn(W1, b1, W2, b2, xb, yb):
44    z = forward(W1, b1, W2, b2, xb)
45    if loss == "ce":
46        p = softmax(z)
47        return -np.mean(np.sum(yb * np.log(p + 1e-12), axis=1))
48    return np.mean((z - yb) ** 2)
输入
xb (b,784) yb (b,10)
输出
标量 —— 一个 Python float，不是一个张量

为什么是「标量」这件事很重要：因为第 50 行的 grad() 只能对标量输出求梯度。 如果 loss_fn 返回形状 (b,10) 的东西，autograd 会直接报错。 这个「标量」就是整个反向传播的起点 —— 你的接口契约在这里收束成一个点，然后再散开成四个梯度。

第 47 行里三个细节都值得知道存在（不必知道推导）： sum(..., axis=1) 是在 10 个类别上求和、 mean 是在 b 个样本上求平均（所以 loss 与 batch 大小无关，好比较）、 +1e-12 是防止 log(0) 变成 -inf。

第 48 行的 MSE 分支保留了，注释写着「能跑但很慢」。原因不在数学错误， 而在梯度形状：MSE 配 sigmoid 类的输出会梯度消失，收敛慢很多。分类任务默认就该是 CE。

06

反向与更新：一行求导，十行 Adam

可黑盒

这一节的全部意义是让你知道「这里发生了什么」，而不是「这里怎么算」。

50grads = grad(loss_fn, argnum=[0, 1, 2, 3])

一行。返回的是一个函数，调用 grads(*P, xb, yb) 就得到四个梯度， 形状和 P 里四个张量一一对应：(784,h) (1,h) (h,10) (1,10)。 梯度必须和参数同形状，这是它唯一的接口约束，也是你唯一需要记住的事。 

69for i in range(4):
70    if optimizer == "adam":
71        m[i] = 0.9 * m[i] + 0.1 * gs[i]
72        v[i] = 0.999 * v[i] + 0.001 * gs[i] ** 2
73        # 偏差修正要用 step，不能用 epoch
74        bc1 = 1 - 0.9 ** step
75        bc2 = 1 - 0.999 ** step
76        P[i] = P[i] - lr * (m[i] / bc1) / (np.sqrt(v[i] / bc2) + 1e-8)
77    else:
78        P[i] = P[i] - lr * gs[i]

你能读懂的部分：m 是梯度的滑动平均（记住方向），v 是梯度平方的滑动平均 （记住幅度），最后两行就是「沿着平均方向、按平均幅度缩放」走一步。 1e-8 是防止除零。这三个常数（0.9 / 0.999 / 1e-8）不要动， 它们被验证了十年，动了没有收益。

坑 · 第 73 行那句注释是这道题唯一的考点 m 和 v 都从 0 开始，前几步必然偏小。偏差修正就是把它们放大回正常尺度： 修正系数取决于更新了多少次，而不是跑了多少轮。 在 batch_size=128、60000 张图的情况下，1 个 epoch 里有 469 次更新 —— 如果用 epoch 当指数，修正会偏小几十倍，学习率等价于被吃掉一大截，前几轮几乎不学习。 这个错误不报错、不崩溃，只是收敛变慢，所以特别难查。

第 56 行 step = 0 和循环里的 step += 1 就是为了这件事单独维护的计数器。 这也是「接口层」的一个典型例子：epoch 和 step 在语义上是两个不同的量， 只是碰巧都由同一个循环驱动。把它们混用，就是语义层张冠李戴。

你可以完全跳过的东西 tanh 的导数是 1 - tanh²、交叉熵对 logits 的梯度是 P̂ - Y、 Adam 的收敛性证明。这三样加起来是几十页教材，而在本文件里它们被 grad() 压缩成了一行。
07

三个循环变量：epoch、step、batch 别搞混

你负责

训练循环（L58–86）是个双层嵌套。三层含义只有一个被写在变量名里。

概念含义本例数值改大了会怎样
epoch把整个训练集完整看一遍10更充分，也可能过拟合
batch_size一次梯度更新用多少张图128更稳但更慢，显存/内存吃得更多
step参数被实际更新了多少次10 × 469 = 4,690它不是你设的，是被算出来的

关系是 step = epoch × ceil(N / batch_size)。N=60000、batch=128 时每轮 469 步（最后一轮不满 128 也走一次）。 这就是为什么第 73 行不能用 epoch —— 两者差了 469 倍。 

59idx = rng.permutation(n)          # 每轮打乱
62for start in range(0, n, batch_size):
63    b = idx[start:start + batch_size]
64    xb, yb = X[b], Y[b]

第 64 行 X[b] 是花式索引，出来的形状是 (b,784)， Y[b] 是 (b,10)。这两个第一维必须相等 —— 否则后面 loss 里的 yb * np.log(p) 会在第 0 维报错。这是形状契约在训练循环里唯一真正发挥作用的地方。

一个小细节，体现作者懂契约 第 80 行 total_loss += loss_fn(...) * len(b) —— 乘上 len(b) 再在第 86 行 除以 n，是为了让最后那个不满 128 的残批按实际样本数加权。 否则一个只有 32 张图的残批会和满批等权，把显示的 loss 拉偏。

评估：训练集和测试集是两条永不相交的线

你负责

评估代码只有四行，但它决定了你前面所有工作有没有意义。

82acc = np.mean(np.argmax(forward(*P, X), axis=1) == labels)   # 每轮，训练集

178logits = predict(X_test, mlp)                                 # 最后，测试集
181acc = np.mean(pred == y_test)
  • 训练集准确率（L82）在循环里每轮算一次，作用是看「学没学会」。它涨到 99% 是很正常的，不代表泛化好。
  • 测试集准确率（L181）只在最后算一次，作用是看「换个数据还认不认得」。这才是你该报给别人的数。
  • 两者差距才是信息：训练 99% / 测试 90% = 过拟合；两个都 92% = 欠拟合或者撞上线性天花板。

本工程实测：隐藏层 256、10 轮、batch 128，训练集 99%+ / 测试集 97.61%。 两个数只差 1.4 个百分点，说明还没过拟合，容量是够的；想再往上就得换卷积（CNN 能到 99%+）， 单纯加宽这一层收益已经很小 —— 这是「加旋钮之前先想清楚瓶颈在哪」的典型例子。

坑 · 第 82 行其实很贵 它每一轮都对全部 60000 张图做一次前向，而训练本身只用 batch 大小。10 轮就是 10 次全量前向， 在纯 NumPy 下是可观的开销。如果想快，可以把它改成只抽 2000 张， 或者干脆每 2 轮算一次 —— 这属于「可优化的接口」，不影响正确性。

契约层最严格的地方

这段 JS 就是把 np.tanh(xb @ W1 + b1) @ W2 + b2 手工展开成三层循环， 因为浏览器里没有矩阵库。注意它读的是 M.arch 动态取 HID、 IN、OUT —— 所以改隐藏层大小，网页不用改。

假契约 · 这是全文最值得看的一处 JSON 里老老实实写着 "activation": "tanh" 和 "output": "softmax"， 但 index.html 从头到尾没有读过这两个字段，它直接硬编码了 Math.tanh。 所以：你把 Python 里的 tanh 改成 relu、重新导出、打开网页 —— 网页会照常运行，照常显示数字，只是全部认错。契约写在了数据里，消费方却没读，等于没写。
更隐蔽的一处 · 预处理也是契约 "input": "28x28 grayscale, /255, white digit on black" 只是一句人类可读的字符串，没有任何东西强制执行它。 而 index.html 里 preprocess() 手工复刻了 MNIST 官方的处理流程： 裁到墨迹边界 → 长边缩到 20×20 → 按重心居中到 28×28。 这三步只要有一处跟训练数据不一致，模型看到的分布就变了，识别率断崖下跌 —— 而且它会「看起来在工作」，只是经常认错。这是手写板 Demo 最常见的失败原因。

这一节是「接口层负责制」真正兑现价值的地方。不会推梯度没关系，会按表排查就够了。

四个旋钮：你实际会改的东西就这些

你负责

除了这四个数，其余代码可以原样不动地跑一辈子。

n_hidden
当前 256。容量。太小欠拟合（92%），太大过拟合 + 导出文件变胖。32 / 64 / 128 / 256 依次试，看测试集准确率的边际收益什么时候消失。
lr
当前 1e-3。步长。Adam 的标准起点就是 1e-3。改成 1e-2 通常开始震荡，1e-1 直接 NaN。
epochs
当前 10。看训练准确率什么时候饱和，饱和之后继续跑只是在拟合噪声。
batch_size
当前 128。折中项：小批噪声大但更新频繁，大批稳定但步数少。纯 NumPy 训练时它对速度影响最大。

建议你做三个对照实验

每个实验只改一个变量，跑完记下测试集准确率。这三个实验的信息量，比读十篇教程大。

  1. 删掉 tanh（L41 改成 return (xb @ W1 + b1) @ W2 + b2）。预期掉到 92% 左右，形状不出错、不报错。
  2. 去掉 /255（L163 把 / 255.0 拿掉）。预期 loss 曲线明显异常，或者收敛极慢。
  3. n_hidden 从 32 调到 256，其他不动。观察参数量从 25,450 涨到 203,530，测试准确率涨了多少 —— 这个差值就是「容量买来的性能」的价格。
这套做法叫什么 有人叫它「vibe coding」，其实更准确的名字是接口层负责制： 内部随便黑，但进去的形状、出来的语义、验收的标准，必须写死在你的脑子里。 你已经在做的事 —— 在写代码之前先推出 (100,784) × (784,32) → (100,32) × (32,10) → (100,10) —— 恰好是这件事里最难、也最不能被替代的部分。
文件对应关系：mnist_loader.py 负责第 1 步，mnist_mlp.py 负责第 2–10 步， web/index.html 负责第 11 步。三个文件之间只通过「形状 + 语义」相连，没有别的东西。
